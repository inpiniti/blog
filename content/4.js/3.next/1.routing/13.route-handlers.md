---
title: 경로 핸들러(Route Handlers)
---

Next.js의 **경로 핸들러(Route Handlers)**는 **서버 측 로직**을 처리하기 위해 사용하는 기능입니다.  
즉, **API 경로**를 만들고 데이터를 처리하거나 외부 요청에 응답할 때 사용합니다. 이는 별도의 백엔드 서버 없이도 간단한 API를 구성하는 데 유용합니다.

---

### 1. **경로 핸들러의 기본 개념**

Next.js의 경로 핸들러는 `/app` 디렉터리 내부에 위치하며, 특정 경로에 **`route.js`** 또는 **`route.ts`** 파일을 추가하면 됩니다. 이 파일은 **HTTP 요청에 대한 응답**을 정의합니다.

---

### 2. **경로 핸들러 설정하기**

다음은 **`GET`, `POST`, `PUT`, `DELETE`** 같은 HTTP 메서드를 처리하는 경로 핸들러의 예시입니다.

#### 예제: 기본 경로 핸들러

```
/app/api/hello/route.js
```

```javascript
export async function GET(request) {
  return new Response('Hello, Next.js!', {
    status: 200,
  });
}
```

- 사용자가 `/api/hello` 경로로 **GET 요청**을 보내면, **"Hello, Next.js!"**라는 응답을 받게 됩니다.

---

### 3. **POST 요청 처리하기**

경로 핸들러에서는 **POST 요청**도 쉽게 처리할 수 있습니다.

#### 예제: `POST` 요청 처리

```javascript
export async function POST(request) {
  const body = await request.json();
  return new Response(`Hello, ${body.name}!`, {
    status: 200,
  });
}
```

- 사용자가 `/api/hello` 경로로 **POST 요청**을 보내면서 `{ "name": "Alice" }` 데이터를 포함하면, **"Hello, Alice!"**라는 응답을 받게 됩니다.

---

### 4. **HTTP 메서드에 따른 핸들러 분기**

경로 핸들러는 **여러 HTTP 메서드(GET, POST, DELETE 등)**를 지원하며, 각 메서드에 대해 개별적으로 핸들러를 정의할 수 있습니다.

#### 예제: 다양한 메서드 처리

```javascript
export async function GET() {
  return new Response('GET 요청입니다.', { status: 200 });
}

export async function POST() {
  return new Response('POST 요청입니다.', { status: 200 });
}

export async function DELETE() {
  return new Response('DELETE 요청입니다.', { status: 200 });
}
```

---

### 5. **경로 핸들러에서 데이터 처리하기**

#### 예제: 쿼리 매개변수 사용하기

```javascript
export async function GET(request) {
  const { searchParams } = new URL(request.url);
  const name = searchParams.get('name') || '익명';
  return new Response(`Hello, ${name}!`, { status: 200 });
}
```

- 사용자가 `/api/hello?name=Bob` 경로로 요청을 보내면, **"Hello, Bob!"**이라는 응답을 받게 됩니다.

---

### 6. **JSON 응답 처리하기**

API에서는 보통 **JSON 형식**으로 데이터를 주고받습니다.

#### 예제: JSON 응답 반환

```javascript
export async function GET() {
  const data = { message: '안녕하세요, Next.js입니다!' };
  return new Response(JSON.stringify(data), {
    status: 200,
    headers: { 'Content-Type': 'application/json' },
  });
}
```

- 이 핸들러는 **JSON 데이터**로 응답을 반환합니다.

---

### 7. **미들웨어와 에러 처리하기**

경로 핸들러 내부에서 **예외 처리**와 **에러 응답**도 구현할 수 있습니다.

#### 예제: 에러 처리

```javascript
export async function GET() {
  try {
    // 일부 처리 로직
    throw new Error('문제가 발생했습니다!');
  } catch (error) {
    return new Response(error.message, { status: 500 });
  }
}
```

- 오류가 발생하면 **500 에러**와 함께 `"문제가 발생했습니다!"` 메시지를 반환합니다.

---

### 8. **쿠키와 헤더 사용하기**

경로 핸들러에서는 **쿠키 설정** 및 **헤더 조작**도 가능합니다.

#### 예제: 쿠키 설정하기

```javascript
export async function GET() {
  const response = new Response('쿠키가 설정되었습니다.', { status: 200 });
  response.headers.set('Set-Cookie', 'user=Alice; Path=/');
  return response;
}
```

- 이 핸들러는 **`user=Alice`** 쿠키를 설정합니다.

---

### 9. **실시간 데이터와 웹소켓 지원**

Next.js 경로 핸들러는 실시간 데이터 처리를 위한 **웹소켓**과 같은 기술도 지원합니다. 이를 통해 **채팅 기능**이나 **실시간 알림**을 구현할 수 있습니다.

---

### 10. **API 최적화 팁**

- **캐시 헤더**를 사용해 응답을 최적화하세요.  
- **정확한 상태 코드**를 반환해 클라이언트가 올바르게 응답을 처리하도록 만드세요.  
- **쿼리 매개변수와 동적 경로**를 사용해 다양한 데이터를 처리할 수 있습니다.

---

### **정리**

- Next.js의 **경로 핸들러**는 **API 엔드포인트**를 쉽게 정의할 수 있게 해줍니다.  
- 다양한 HTTP 메서드(GET, POST 등)를 처리하고, **JSON 응답**과 **쿠키 설정**도 가능합니다.  
- 별도의 서버 없이 **Next.js 애플리케이션 내부에서 API를 구현**할 수 있어 효율적입니다.

경로 핸들러를 활용하면 **서버와 클라이언트 사이의 데이터 흐름을 유연하게 제어**할 수 있습니다. 이를 통해 더 강력한 **풀스택 애플리케이션**을 손쉽게 개발할 수 있습니다! 🚀
