---
title: 데이터 가져오기(Fetching Data)
---

Next.js에서는 **서버에서 데이터 가져오기(SSR, SSG)**와 **클라이언트 측 데이터 가져오기(CSR)**를 모두 지원합니다. 이를 통해 **페이지 로딩 속도와 SEO**를 최적화하거나 **실시간 데이터**를 다룰 수 있습니다.

---

### 1. **서버 측 데이터 가져오기(Server-side Rendering - SSR)**

**서버 측에서 매 요청마다 데이터를 가져와** 페이지를 생성합니다. 사용자가 페이지를 열 때 서버가 데이터를 받아와 완성된 HTML을 렌더링합니다.

#### 예제: `getServerSideProps`
```javascript
export async function getServerSideProps() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const data = await res.json();

  return {
    props: { posts: data },
  };
}

export default function Home({ posts }) {
  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **`getServerSideProps`**는 매 요청마다 실행되어 최신 데이터를 제공합니다.
- SEO가 중요한 페이지나 **자주 바뀌는 데이터**에 유용합니다.

---

### 2. **정적 생성(Static Generation - SSG)**

빌드 시점에 데이터를 가져와 **정적 HTML 파일**을 생성합니다.  
정적 파일은 **빠른 로딩**과 **SEO**에 유리합니다.

#### 예제: `getStaticProps`
```javascript
export async function getStaticProps() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const data = await res.json();

  return {
    props: { posts: data },
  };
}

export default function Home({ posts }) {
  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **`getStaticProps`**는 빌드 시점에 실행되며, 정적 파일로 만들어집니다.
- 자주 바뀌지 않는 콘텐츠나 **SEO가 중요한 페이지**에 적합합니다.

---

### 3. **증분 정적 재생성(ISR - Incremental Static Regeneration)**

**정적 생성**을 사용하면서 일정 시간마다 데이터를 다시 가져와 **정적 파일을 업데이트**합니다.

#### 예제: ISR 사용하기
```javascript
export async function getStaticProps() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const data = await res.json();

  return {
    props: { posts: data },
    revalidate: 60, // 60초마다 데이터 갱신
  };
}
```

- **`revalidate`** 옵션으로 **지정된 시간마다** 페이지가 재생성됩니다.
- 최신 데이터가 필요하지만, 서버 부하를 줄이고 싶은 경우 유용합니다.

---

### 4. **클라이언트 측 데이터 가져오기(Client-side Rendering - CSR)**

페이지가 로드된 후 **클라이언트 측에서 데이터를 가져와** 표시합니다.  
이 방법은 주로 **비동기 데이터**나 **사용자 상호작용**이 필요한 경우 사용됩니다.

#### 예제: 클라이언트 측 데이터 가져오기
```javascript
import { useEffect, useState } from 'react';

export default function Home() {
  const [posts, setPosts] = useState([]);

  useEffect(() => {
    fetch('https://jsonplaceholder.typicode.com/posts')
      .then((res) => res.json())
      .then((data) => setPosts(data));
  }, []);

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- 페이지 로드 후 데이터가 **비동기적으로** 가져와집니다.
- 로그인 정보나 **사용자 맞춤 데이터**가 필요한 경우에 적합합니다.

---

### 5. **서버 구성 요소에서 데이터 가져오기(Server Components)**

Next.js는 **서버 구성 요소(Server Components)**를 통해 서버에서 직접 데이터를 가져와 렌더링할 수 있습니다.

#### 예제: 서버 구성 요소 사용
```javascript
// app/page.js
export default async function Home() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- 서버 구성 요소에서는 데이터를 직접 **await**로 처리할 수 있습니다.
- **SEO 최적화**와 **빠른 렌더링**에 적합합니다.

---

### 6. **데이터 가져오기 방법 비교**

| **방법**                  | **사용 시점**                 | **장점**                           | **단점**                      |
|-------------------------|----------------------------|--------------------------------|-----------------------------|
| SSR                     | 요청 시점                   | 최신 데이터 제공, SEO 가능      | 요청마다 서버 부하 발생         |
| SSG                     | 빌드 시점                   | 빠른 로딩, SEO 최적화           | 데이터가 자주 바뀌면 부적합      |
| ISR                     | 빌드 후 일정 주기로 갱신       | 최신 데이터와 정적 파일의 장점 결합 | 일정 시간 동안 오래된 데이터 제공 |
| CSR                     | 클라이언트 로드 후            | 비동기 데이터, 사용자 맞춤 제공 | SEO에 불리함                   |
| 서버 구성 요소(Server Components) | 서버에서 직접 처리 | 빠르고 효율적, SEO 지원 | 일부 복잡한 로직에 제한 있음 |

---

### **정리**

- **SSR**은 매 요청마다 데이터를 가져오고, **SSG**는 빌드 시점에 데이터를 가져옵니다.
- **ISR**은 일정 시간마다 정적 페이지를 갱신하고, **CSR**은 클라이언트에서 데이터를 가져옵니다.
- **서버 구성 요소**를 활용하면 서버에서 데이터를 가져오는 작업이 더 쉬워집니다.

Next.js의 다양한 데이터 가져오기 방법을 잘 활용하면, **최신 데이터**와 **빠른 로딩 속도**를 모두 충족하는 웹 애플리케이션을 개발할 수 있습니다! 🚀
