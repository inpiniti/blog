이 기능을 통해 데이터를 효율적으로 관리하고, 서버 부하를 줄이며 최신 데이터를 빠르게 제공할 수 있습니다.

---

## **Next.js에서 캐싱과 재검증이 중요한 이유**

- **빠른 로딩 시간**: 캐시된 데이터를 사용해 로딩 시간을 단축합니다.
- **서버 부하 감소**: 동일한 데이터를 여러 번 요청하지 않도록 합니다.
- **최신 데이터 보장**: 필요할 때만 데이터를 다시 가져와 새롭게 갱신합니다.

Next.js는 이를 위해 **캐싱, 정적 생성(SSG), 증분 정적 재생성(ISR)** 같은 다양한 기술을 제공합니다.

---

## **1. 캐싱(fetch의 기본 옵션 활용)**

Next.js는 기본적으로 서버 구성 요소(Server Components)와 클라이언트 구성 요소(Client Components) 모두에서 **`fetch` API**를 사용할 수 있습니다.  
**`fetch` API**는 캐시와 관련된 몇 가지 옵션을 제공합니다.

#### 예제: `fetch`의 캐시 옵션 사용
```javascript
export default async function Home() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    cache: 'force-cache', // 강제로 캐시 사용
  });
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **`cache: 'force-cache'`**: 캐시된 데이터를 사용하며, 네트워크 요청을 피합니다.
- **`cache: 'no-store'`**: 항상 새 데이터를 가져오고, 캐시를 사용하지 않습니다.

---

## **2. 정적 데이터와 ISR을 사용한 캐싱**

정적 생성(SSG)과 증분 정적 재생성(ISR)을 통해 데이터를 캐싱하고 **필요할 때만 재검증**합니다.

#### 예제: ISR로 페이지 재검증
```javascript
export async function getStaticProps() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const data = await res.json();

  return {
    props: { posts: data },
    revalidate: 60, // 60초마다 데이터 갱신
  };
}
```

- **`revalidate`**: 페이지가 생성된 후 **60초마다** 새롭게 데이터를 가져옵니다.
- ISR은 **자주 업데이트되는 데이터**를 다룰 때 유용합니다.

---

## **3. `fetch`의 `next` 옵션으로 고급 캐싱 설정**

Next.js는 **`fetch`에 `next` 옵션**을 추가해 더 세밀하게 캐시와 재검증을 제어할 수 있습니다.

#### 예제: `fetch`의 `next` 옵션 사용
```javascript
export default async function Home() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    next: { revalidate: 10 }, // 10초마다 캐시 재검증
  });
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **`next.revalidate`**: 해당 데이터는 10초마다 **재검증**됩니다.
- **`next` 옵션**을 사용하면 페이지 전체가 아닌 **개별 fetch 요청 단위**로 재검증을 제어할 수 있습니다.

## **4. 데이터 불변성 보장과 `no-store` 사용**

경우에 따라 최신 데이터를 항상 가져와야 할 수 있습니다. 이때는 **`no-store`** 옵션을 사용합니다.

#### 예제: 항상 최신 데이터 가져오기
```javascript
export default async function Home() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    cache: 'no-store', // 항상 새 데이터 요청
  });
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **`no-store`**: 모든 요청이 서버에서 새 데이터를 가져옵니다.
- 이 옵션은 **최신 정보**가 중요한 페이지에 사용됩니다.

## **5. 클라이언트 측에서 데이터 재검증**

클라이언트 측에서 비동기 데이터가 필요할 때는 **SWR(중복 요청 방지)** 라이브러리를 사용하는 것이 좋습니다.

#### 예제: SWR 사용하기
```javascript
import useSWR from 'swr';

const fetcher = (url) => fetch(url).then((res) => res.json());

export default function Home() {
  const { data, error } = useSWR('https://jsonplaceholder.typicode.com/posts', fetcher);

  if (error) return <div>Failed to load</div>;
  if (!data) return <div>Loading...</div>;

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {data.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **SWR**은 데이터가 변경될 때만 가져오기 때문에 **중복 요청을 줄여** 성능을 최적화합니다.
- 클라이언트 측 데이터 갱신에 유용합니다.

---

## **6. 데이터 가져오기 전략 요약**

| **전략**                   | **사용 시점**                   | **장점**                         | **단점**                       |
|--------------------------|-----------------------------|-------------------------------|-------------------------------|
| **SSG + ISR**             | 빌드 시점 + 주기적 갱신         | 빠른 로딩 + 최신 데이터        | 데이터가 자주 바뀌면 부적합     |
| **SSR**                   | 요청 시점                    | 최신 데이터 제공                | 요청마다 서버 부하 발생          |
| **CSR + SWR**             | 클라이언트 로드 후              | 중복 요청 방지, 실시간 갱신      | 초기 로딩 속도가 느릴 수 있음    |
| **`cache: 'no-store'`**  | 요청 시점마다                | 최신 데이터 보장                | 성능 저하 가능                  |

---

### **정리**

- **캐시**를 활용하면 **성능을 최적화**하고 서버 부하를 줄일 수 있습니다.
- **ISR**과 **`revalidate`** 옵션은 **최신 데이터**와 **빠른 로딩**을 동시에 제공합니다.
- 클라이언트 측에서는 **SWR**로 데이터를 효율적으로 관리할 수 있습니다.
