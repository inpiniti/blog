## **1. 서버 구성 요소(Server Components)란?**

- 서버 구성 요소는 **서버에서만 실행**되며, 클라이언트로 **최적화된 HTML**을 전송합니다.
- 서버와 클라이언트의 역할을 명확하게 분리해 **렌더링 성능을 높이고** 번들 크기를 줄입니다.
- **데이터베이스나 API 호출** 같은 서버 측 작업을 직접 처리할 수 있어 **코드 복잡성을 줄여줍니다**.

---

### **서버 구성 요소의 주요 특징**  

1. **서버에서만 실행**: 클라이언트에 노출되지 않습니다.
2. **JS 없는 렌더링**: JavaScript를 사용하지 않고 HTML만 렌더링해 성능을 최적화합니다.
3. **무거운 연산 처리에 적합**: 데이터베이스 접근, API 호출 등을 서버에서 처리합니다.
4. **상태 관리가 필요 없는 UI**에 적합: 단순한 UI나 동적 기능이 필요 없는 부분에 좋습니다.

---

## **2. 서버 구성 요소의 기본 사용법**

서버 구성 요소는 기본적으로 `.jsx` 또는 `.tsx` 파일에서 작성할 수 있으며, 별도의 설정 없이 서버에서 렌더링됩니다.

### **예제: 서버 구성 요소 만들기**

```javascript
// app/page.jsx

export default async function HomePage() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- 이 코드는 **서버 측에서 실행**되며, 클라이언트로 HTML을 전송합니다.
- **API 호출**이 서버에서 처리되기 때문에 클라이언트는 응답된 HTML만 받아서 빠르게 렌더링합니다.

---

## **3. 서버 구성 요소와 클라이언트 구성 요소의 차이**

- **서버 구성 요소**는 서버에서만 실행되며, 클라이언트에 **JS 없이 HTML만 전송**됩니다.
- **클라이언트 구성 요소**는 클라이언트에서 실행되고, 상호작용이 필요한 UI에 사용됩니다.

### **클라이언트 구성 요소와 함께 사용하기**

서버 구성 요소 안에서 **클라이언트 구성 요소**를 임포트할 수 있습니다.

```javascript
// app/page.jsx
import Counter from './Counter';

export default async function HomePage() {
  return (
    <div>
      <h1>Home Page</h1>
      <Counter /> {/* 클라이언트 구성 요소 */}
    </div>
  );
}
```

```javascript
// app/Counter.jsx
"use client";

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}
```

- **Counter**는 **클라이언트 구성 요소**로 선언되었고, 상호작용이 필요한 부분에 사용됩니다.
- **서버 구성 요소**는 클라이언트 구성 요소를 감싸 **상호작용과 정적 렌더링을 동시에 활용**할 수 있습니다.

---

## **4. 서버 구성 요소의 이점**  

1. **더 나은 성능**: 서버에서 필요한 데이터를 미리 렌더링해 클라이언트로 전송합니다.
2. **클라이언트 번들 크기 감소**: 서버에서만 동작하기 때문에 클라이언트로 전송되는 JavaScript가 줄어듭니다.
3. **보안 강화**: 서버 구성 요소는 서버에서만 동작하기 때문에 민감한 정보가 노출되지 않습니다.
4. **SEO 개선**: 완전한 HTML이 클라이언트에 전달되어 검색 엔진 최적화에 유리합니다.

---

## **5. 서버 구성 요소의 제약사항**

- **브라우저 API 사용 불가**: 서버에서 실행되므로 `window`, `document`와 같은 브라우저 객체를 사용할 수 없습니다.
- **상태 관리 제한**: 서버 구성 요소는 상태를 유지할 수 없기 때문에, **상호작용이 필요 없는 UI**에 적합합니다.
- **클라이언트 구성 요소에 의존**: 상호작용이 필요한 경우 반드시 클라이언트 구성 요소와 함께 사용해야 합니다.

---

## **6. 서버 구성 요소와 데이터 가져오기 전략**  

서버 구성 요소 안에서 데이터를 가져올 때, **서버의 장점**을 최대한 활용할 수 있습니다.

### **API 호출 예제: 서버 구성 요소에서 데이터 가져오기**

```javascript
// app/page.jsx

export default async function ProductsPage() {
  const res = await fetch('https://fakestoreapi.com/products');
  const products = await res.json();

  return (
    <div>
      <h1>Products</h1>
      <ul>
        {products.map((product) => (
          <li key={product.id}>{product.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- 이 코드는 서버 측에서 API 데이터를 가져와 **완전한 HTML로 렌더링**합니다.
- 클라이언트는 **추가 요청 없이** 최적화된 HTML을 바로 렌더링합니다.

---

### **데이터 캐싱과 재검증(ISR) 활용**

서버 구성 요소는 **캐싱**과 **재검증**을 통해 성능을 더욱 높일 수 있습니다.

```javascript
export default async function HomePage() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    next: { revalidate: 60 }, // 60초마다 재검증
  });
  const posts = await res.json();

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

- **ISR(Incremental Static Regeneration)**을 활용해 60초마다 데이터를 갱신합니다.
- 사용자는 **최신 데이터와 빠른 로딩 속도**를 동시에 경험할 수 있습니다.

---

### **정리**

- 서버 구성 요소는 서버 측에서 렌더링되어 **성능과 보안**을 극대화합니다.
- **API 호출**과 같은 서버 작업을 직접 처리하며, 클라이언트로 **최적화된 HTML**을 전송합니다.
- 상호작용이 필요한 경우 **클라이언트 구성 요소**와 함께 사용해야 합니다.

Next.js의 **서버 구성 요소**를 잘 활용하면, 성능과 유지보수 측면에서 **더 효율적인 애플리케이션**을 만들 수 있습니다. 🚀
