---

## **1. 구성 패턴이란?**  
구성 패턴은 컴포넌트를 **작고 재사용 가능한 단위로 나누고** 서로 조합해 UI를 만드는 기법입니다. 이를 통해 **복잡한 인터페이스를 효율적으로 개발**할 수 있고, **유지보수와 확장성**을 높일 수 있습니다.

### **왜 구성 패턴을 사용할까요?**
- **코드 재사용성** 증가  
- **유연한 구성**으로 다양한 UI 요구 사항 대응  
- **더 읽기 쉽고 유지보수 가능한 코드** 작성  

---

## **2. 자주 사용하는 구성 패턴**  

### **(1) 컨테이너와 프레젠테이션 패턴(Container-Presenter Pattern)**  
- **컨테이너 컴포넌트**: 상태 관리와 로직을 담당합니다.  
- **프레젠테이션 컴포넌트**: UI를 렌더링하며, 상태나 로직을 알지 못합니다.

#### **예제:**

```javascript
// Container.jsx
"use client";
import { useState } from 'react';
import Presenter from './Presenter';

export default function Container() {
  const [count, setCount] = useState(0);

  return <Presenter count={count} increment={() => setCount(count + 1)} />;
}
```

```javascript
// Presenter.jsx
export default function Presenter({ count, increment }) {
  return (
    <div>
      <p>카운트: {count}</p>
      <button onClick={increment}>증가</button>
    </div>
  );
}
```

**사용 시기**: 복잡한 비즈니스 로직과 UI를 분리하고 싶을 때.

---

### **(2) HOC(High Order Component) 패턴**  
- **HOC**는 컴포넌트를 감싸서 **새로운 기능을 추가**하는 패턴입니다.

#### **예제:**

```javascript
function withLogger(Component) {
  return function WrappedComponent(props) {
    console.log('컴포넌트 렌더링:', props);
    return <Component {...props} />;
  };
}

const LoggedComponent = withLogger(Presenter);
```

**사용 시기**: 로깅, 권한 부여 등의 기능을 컴포넌트에 추가하고 싶을 때.

---

### **(3) Render Props 패턴**  
- **함수를 props로 전달**하여 컴포넌트 간에 유연한 데이터 공유를 합니다.

#### **예제:**

```javascript
export default function Counter({ render }) {
  const [count, setCount] = useState(0);

  return render(count, () => setCount(count + 1));
}
```

```javascript
<Counter
  render={(count, increment) => (
    <div>
      <p>카운트: {count}</p>
      <button onClick={increment}>증가</button>
    </div>
  )}
/>
```

**사용 시기**: 컴포넌트 간 **동적 렌더링이 필요할 때** 유용합니다.

---

### **(4) Provider 패턴 (Context API)**  
- 여러 컴포넌트에서 **공유되는 상태**를 관리합니다.

#### **예제:**

```javascript
import { createContext, useContext, useState } from 'react';

const CounterContext = createContext();

export function CounterProvider({ children }) {
  const [count, setCount] = useState(0);
  return (
    <CounterContext.Provider value={{ count, setCount }}>
      {children}
    </CounterContext.Provider>
  );
}

export function useCounter() {
  return useContext(CounterContext);
}
```

```javascript
import { useCounter } from './CounterProvider';

export default function CounterDisplay() {
  const { count, setCount } = useCounter();
  return (
    <div>
      <p>카운트: {count}</p>
      <button onClick={() => setCount(count + 1)}>증가</button>
    </div>
  );
}
```

**사용 시기**: 여러 컴포넌트에서 **공유 상태**가 필요할 때.

---

## **3. 구성 패턴의 선택 기준**  
- **복잡한 상태 관리**가 필요한 경우: **컨테이너와 프레젠테이션 패턴**  
- **특정 기능을 여러 컴포넌트에 추가**하고 싶을 때: **HOC 패턴**  
- **상황에 따라 동적 렌더링**이 필요한 경우: **Render Props 패턴**  
- **전역 상태가 필요**한 경우: **Provider 패턴**  

---

## **4. 서버와 클라이언트 구성 요소 조합**  
Next.js에서는 **서버 구성 요소**와 **클라이언트 구성 요소**를 조합해 최적의 성능을 얻을 수 있습니다.

#### **예제: 서버 구성 요소에서 클라이언트 구성 요소 사용하기**

```javascript
// app/page.jsx
import CounterDisplay from './CounterDisplay';
import { CounterProvider } from './CounterProvider';

export default function HomePage() {
  return (
    <CounterProvider>
      <h1>홈페이지</h1>
      <CounterDisplay />
    </CounterProvider>
  );
}
```

이 방식으로 클라이언트 구성 요소의 상태와 상호작용을 처리하면서도 서버 구성 요소의 성능 최적화를 활용할 수 있습니다.

---

## **5. 정리**  

Next.js의 **구성 패턴**을 사용하면 복잡한 애플리케이션도 **유연하고 유지보수하기 쉽게** 만들 수 있습니다. 각 패턴은 특정 상황에서 **최적의 코드 구조**를 제공하며, **서버와 클라이언트 구성 요소**를 조합하면 더욱 강력한 애플리케이션을 개발할 수 있습니다.

- **컨테이너와 프레젠테이션 패턴**: UI와 로직 분리  
- **HOC 패턴**: 컴포넌트에 기능 추가  
- **Render Props 패턴**: 동적 렌더링  
- **Provider 패턴**: 전역 상태 관리  

구성 패턴을 잘 활용하면 **더 나은 코드 품질과 유지보수성**을 보장할 수 있습니다. 🚀
