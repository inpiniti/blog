---
title: Caching(캐싱)
description: 캐싱(Caching)은 데이터를 미리 저장해 필요할 때 빠르게 가져오는 방법입니다.
---

## **1. 캐싱이란 무엇인가?**  
- **캐싱**은 데이터를 **한 번 가져와 저장**한 뒤, 나중에 동일한 요청이 들어오면 **미리 저장된 데이터를 사용**하는 방식입니다.  
- 이를 통해 **서버 부하를 줄이고** 페이지의 **응답 속도를 크게 향상**시킬 수 있습니다.

---

## **2. 캐싱 유형**  

Next.js에서는 다양한 캐싱 전략을 제공합니다. 주요 옵션은 다음과 같습니다:

| **캐싱 전략**           | **설명**                                                | **사용 시기**                                   |
|-------------------------|--------------------------------------------------------|------------------------------------------------|
| **Static Generation**    | 빌드 시 페이지를 생성하여 캐시                         | 자주 변경되지 않는 정적 페이지에 적합          |
| **Revalidation**         | 캐시된 페이지를 일정 주기로 새로 고침                  | 데이터가 가끔 변경되는 페이지에 적합           |
| **Client-side Cache**    | 브라우저가 클라이언트에서 데이터를 캐시                | 사용자 인터페이스 상의 빠른 응답이 필요할 때   |
| **Server-side Cache**    | 서버에서 캐시된 응답 제공                              | API 호출 최적화 또는 서버 부하 감소에 사용     |
| **Edge Cache**           | Edge 네트워크에서 데이터를 캐시해 지연 시간 최소화      | 글로벌 사용자에게 빠른 응답 제공이 필요할 때   |

---

## **3. Static Generation과 캐싱**  

Next.js에서 **정적 생성(static generation)**은 빌드 시 페이지를 만들어 **캐시**합니다. 이는 **변하지 않는 페이지**에 적합합니다.

```javascript
export async function getStaticProps() {
  const data = await fetch('https://api.example.com/data');
  return {
    props: { data }, // 이 데이터는 빌드 시 캐시됩니다.
  };
}
```

- 빌드 이후 **모든 사용자가 동일한 캐시된 페이지**를 받습니다.  
- 데이터를 자주 변경하지 않는 경우 사용하면 좋습니다.

---

## **4. ISR (Incremental Static Regeneration)과 Revalidation**  

ISR을 사용하면 Next.js는 **정적 페이지를 일정 시간마다 갱신**합니다. 이로써 **최신 데이터를 반영**하면서도 **빠른 성능**을 유지할 수 있습니다.

```javascript
export async function getStaticProps() {
  const data = await fetch('https://api.example.com/data');
  return {
    props: { data },
    revalidate: 60, // 60초마다 페이지를 새로 고침
  };
}
```

- 사용자가 페이지를 요청할 때마다 **최대 60초 이내의 최신 데이터**가 제공됩니다.  
- 자주 업데이트되지만 매번 실시간으로 변경할 필요가 없는 데이터에 적합합니다.

---

## **5. 클라이언트 측 캐싱**  

클라이언트 측에서 데이터를 캐시하면 **사용자 인터페이스가 더욱 빠르게 반응**합니다. 예를 들어, React의 **`SWR`** 훅을 사용해 데이터를 쉽게 캐싱할 수 있습니다.

```javascript
import useSWR from 'swr';

const fetcher = (url) => fetch(url).then((res) => res.json());

export default function Component() {
  const { data, error } = useSWR('/api/data', fetcher);

  if (error) return <div>에러 발생!</div>;
  if (!data) return <div>로딩 중...</div>;

  return <div>데이터: {data.value}</div>;
}
```

- **SWR**은 데이터를 **자동으로 갱신**하고, 캐시된 데이터를 우선적으로 사용합니다.  
- 이는 **반복적인 API 호출**을 줄여 성능을 최적화합니다.

---

## **6. 서버 측 캐싱**  

서버에서 캐시를 사용하면 **API 호출 빈도를 줄이고, 서버 부하를 줄일 수** 있습니다. 예를 들어, Next.js API 경로에서 **Redis**와 같은 캐시를 사용할 수 있습니다.

```javascript
import redis from 'redis';

const client = redis.createClient();

export default async function handler(req, res) {
  const cachedData = await client.get('key');

  if (cachedData) {
    return res.status(200).json(JSON.parse(cachedData));
  }

  const data = await fetch('https://api.example.com/data');
  client.set('key', JSON.stringify(data));

  res.status(200).json(data);
}
```

- **Redis**와 같은 캐시 서버를 활용해 데이터를 효율적으로 관리합니다.  
- 서버 부하를 줄이고, 동일한 데이터를 빠르게 제공할 수 있습니다.

---

## **7. Edge Cache 사용하기**  

Edge 네트워크에서 캐시를 사용하면 **글로벌 사용자**에게도 빠른 응답을 제공합니다. 이는 **전 세계적으로 분산된 CDN**을 통해 작동합니다.

```javascript
export const config = {
  runtime: 'edge', // Edge 런타임에서 캐시 활용
};

export default async function handler(req) {
  const data = await fetch('https://api.example.com/data');
  return new Response(JSON.stringify(data), {
    headers: { 'Cache-Control': 's-maxage=60, stale-while-revalidate' },
  });
}
```

- **`s-maxage`**: 캐시를 **60초 동안 유지**합니다.  
- **`stale-while-revalidate`**: 만료된 캐시도 **백그라운드에서 갱신**하면서 사용합니다.

---

## **8. Cache-Control 헤더 사용하기**  

Next.js는 **HTTP 헤더**를 통해 브라우저와 서버의 캐시 동작을 제어할 수 있습니다.

```javascript
export default function handler(req, res) {
  res.setHeader('Cache-Control', 'public, max-age=60, stale-while-revalidate=300');
  res.json({ message: '캐시된 응답입니다.' });
}
```

- **`public`**: 모든 사용자가 캐시를 사용할 수 있게 설정합니다.  
- **`max-age`**: 60초 동안 캐시를 유지합니다.  
- **`stale-while-revalidate`**: 최대 300초 동안 오래된 데이터를 제공하면서 백그라운드에서 새 데이터를 가져옵니다.

---

## **9. 캐싱 최적화 전략**  

1. **정적 페이지는 빌드 시 캐시**하고, 자주 변경되지 않도록 설정합니다.  
2. **ISR을 사용해 일정 주기로 페이지를 갱신**합니다.  
3. 클라이언트와 서버 측에서 **캐시를 적극 활용**해 불필요한 데이터 요청을 줄입니다.  
4. **Edge 네트워크**를 활용해 글로벌 사용자에게 빠른 응답을 제공합니다.  
5. **Cache-Control 헤더**를 적절히 설정해 브라우저 캐시를 제어합니다.

---

## **10. 정리**  

Next.js에서 캐싱은 성능 최적화의 핵심입니다. **정적 페이지 생성, 클라이언트 및 서버 측 캐싱, Edge 캐시** 등을 적절히 활용하면 **빠른 응답과 효율적인 리소스 사용**을 동시에 달성할 수 있습니다.  

- 정적 페이지는 **빌드 시 캐시**하고, 자주 변경되는 데이터는 **ISR로 갱신**합니다.  
- 클라이언트와 서버 측 캐시를 적극 활용해 **API 호출과 서버 부하를 줄입니다**.  
- **Edge 네트워크**를 활용해 글로벌 사용자를 대상으로 빠른 서비스를 제공합니다.  

이렇게 다양한 캐싱 전략을 활용하면 **빠르고 최적화된 사용자 경험**을 제공할 수 있습니다! 🚀
