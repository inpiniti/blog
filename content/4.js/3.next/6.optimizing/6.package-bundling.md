---

## **1. 번들링과 코드 스플리팅의 기본 개념**  

- **번들링**: 여러 모듈과 패키지를 하나의 파일로 묶는 과정입니다.  
- **코드 스플리팅**: 필요한 코드만 별도의 파일로 분리해 **동적 로딩**으로 로딩 속도를 개선하는 기법입니다.  
- **Next.js**는 페이지 단위로 자동 코드 스플리팅을 수행합니다.

---

## **2. 자동 번들링 최적화**  

Next.js에서는 페이지 단위로 코드를 분리해 각 페이지에 필요한 코드만 로드합니다.  
예를 들어, `/about` 페이지에만 필요한 코드는 홈 페이지에서 로드되지 않습니다.

```javascript
export default function Home() {
  return <h1>홈페이지</h1>;
}
```

`/`(홈) 페이지와 `/about` 페이지는 각각 별도로 번들링되어, 불필요한 코드를 로드하지 않습니다.

---

## **3. 외부 패키지 번들 크기 줄이기**  

### **Tree Shaking**  
Tree Shaking은 **사용되지 않는 코드를 제거**해 번들 크기를 줄이는 최적화 기법입니다. Next.js는 이를 자동으로 처리합니다. 예를 들어, Lodash에서 특정 함수만 가져오는 경우:

```javascript
import { debounce } from 'lodash';
```

위와 같이 필요한 부분만 가져오면, 전체 패키지가 아닌 **`debounce` 함수만 번들에 포함**됩니다.  

---

## **4. `dynamic`을 활용한 동적 import**  

Next.js에서는 **동적 import**를 통해 필요한 순간에만 코드를 로드할 수 있습니다. 

```javascript
import dynamic from 'next/dynamic';

const DynamicComponent = dynamic(() => import('../components/HeavyComponent'));

export default function HomePage() {
  return <DynamicComponent />;
}
```

- **동적 import**는 페이지 초기 로딩 속도를 개선합니다.
- 컴포넌트가 필요할 때만 로드하므로 **성능 최적화**에 효과적입니다.

## **5. 라이브러리의 번들 제외 (Externalizing)**  

때로는 특정 라이브러리를 번들에 포함하지 않고, **CDN이나 외부에서 로드**하는 것이 더 효율적입니다. 예를 들어, `react`와 같은 라이브러리를 제외할 수 있습니다.

```javascript
// next.config.js
module.exports = {
  webpack: (config) => {
    config.externals = {
      react: 'React',
      'react-dom': 'ReactDOM',
    };
    return config;
  },
};
```

이렇게 하면 `react`와 `react-dom`은 번들에 포함되지 않고, **CDN에서 제공**됩니다.

## **6. 모듈 패키지 최적화 (Babel 플러그인 활용)**  

일부 라이브러리에서 **필요한 모듈만 로드**하도록 설정할 수 있습니다. 예를 들어, `@babel/plugin-transform-runtime`을 사용하면 코드 중복을 방지할 수 있습니다.

```bash
npm install @babel/plugin-transform-runtime
```

Babel 설정 파일에서 플러그인을 추가합니다.

```json
{
  "presets": ["next/babel"],
  "plugins": ["@babel/plugin-transform-runtime"]
}
```

이 설정을 통해 **번들 크기를 줄이고 코드 중복을 최소화**할 수 있습니다.

---

## **7. Moment.js 같은 대형 라이브러리 최적화**  

Moment.js와 같은 라이브러리는 번들 크기가 큰 편입니다. Next.js에서는 Moment.js 대신 **day.js**와 같은 경량 라이브러리를 사용하는 것이 좋습니다.

```bash
npm install dayjs
```

```javascript
import dayjs from 'dayjs';

console.log(dayjs().format());
```

## **8. 번들 분석 도구 사용**  

Next.js는 번들 크기를 시각화하는 **`@next/bundle-analyzer`** 도구를 제공합니다.

### **설치 및 사용 방법**  
```bash
npm install @next/bundle-analyzer
```

`next.config.js` 파일에 설정을 추가합니다.

```javascript
const withBundleAnalyzer = require('@next/bundle-analyzer')({
  enabled: process.env.ANALYZE === 'true',
});

module.exports = withBundleAnalyzer({});
```

이제 다음 명령어로 번들을 분석할 수 있습니다.

```bash
ANALYZE=true npm run build
```

---

## **9. 코드 중복 방지 (Deduplication)**  

Next.js는 여러 모듈에서 같은 패키지를 참조할 때 **중복된 모듈을 제거**합니다. 이를 통해 불필요한 번들 크기를 줄일 수 있습니다.

Next.js에서 패키지 번들링을 최적화하면 **페이지 로딩 속도**와 **성능**을 크게 향상시킬 수 있습니다. 동적 import, Tree Shaking, 외부 라이브러리의 번들 제외 등 다양한 기법을 활용해 최적화된 웹 애플리케이션을 만들어 보세요. **번들 분석 도구**를 사용해 문제를 시각화하고 개선점을 찾아내는 것도 중요합니다. 🚀
